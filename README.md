# ①課題名

お宝探しゲーム「深淵の分かれ道」

## ②課題内容（どんな作品か）

- 左右の道を選びながら、全5階層のダンジョンを探索してお宝を集めるブラウザゲームです。
- 道と階層によって成功率・獲得ポイントが変わります。左は成功しやすい道、右は成功率が低い代わりに高得点を狙える道です。
- スタミナはハート3個分。失敗するたびに1個減り、0になるとゲームオーバーで全ポイントを失います。途中で入り口へ戻れば、その時点のポイントを持ち帰れます。
- 探索は最大5ターン。5階層目で成功するとクリアです。さらに進むか、帰還してお宝を確保するかを判断します。

<summary>遊び方・階層ごとの成功率とポイント</summary>

### 遊び方

1. 1階層・スタミナ3・保有ポイント0・残り5ターンからスタートします。
2. 左右の道に表示された成功率と獲得ポイントを見て、進む道を選びます。
3. 成功するとポイントを獲得し、次の階層へ進みます。5階層目で成功すると、その階層のポイントを獲得してゲームクリアです。6階層へは進みません。
4. 失敗するとスタミナが1減り、同じ階層でもう一度挑戦します。成功・失敗にかかわらず、道を選ぶたびに1ターン消費します。
5. スタミナが0になるとゲームオーバーです。保有ポイントが0になり、探索の操作ができなくなります。
6. クリアする前に5ターンを使い切った場合は、探索終了です。スタミナが残っていれば、その時点のポイントを保持して結果を表示します。最終ターンにスタミナが0になった場合は、ゲームオーバーが優先されます。

「入り口へ戻る」を押すと、途中で探索を終了して、その時点のポイントを持ち帰れます。帰還時には到達階層と持ち帰ったポイントを表示します。
クリア・ゲームオーバー・ターン切れ・帰還の後は、左右の選択と帰還のボタンが無効になります。
「やり直す」は探索中も終了後も使えます。スタミナ・階層・ポイント・残りターン・道の成功率と獲得ポイント・結果表示を初期状態に戻し、すべての探索ボタンを再び使えるようにします。

### 道ごとの成功率と獲得ポイント

左の「整備された道」は成功しやすく、右の「崩れかけた道」は成功率が低い代わりに多くのポイントを獲得できます。
深い階層ほど成功率が下がり、成功したときの獲得ポイントが増えます。

| 挑戦する階層 | 左：成功率 | 左：獲得ポイント | 右：成功率 | 右：獲得ポイント |
| --- | --- | --- | --- | --- |
| 1階層 | 80% | 10pt | 50% | 20pt |
| 2階層 | 75% | 20pt | 30% | 40pt |
| 3階層 | 70% | 30pt | 10% | 60pt |
| 4階層 | 65% | 40pt | 5% | 120pt |
| 5階層 | 60% | 50pt | 2% | 240pt |

現在の階層を `n` とすると、左の道は以下の式で計算しています。

- 左の成功率：`80 - (n - 1) × 5`（%）
- 左の獲得ポイント：`n × 10`（pt）

右の道は、`JavaScript/script.js` の `getRoadInfo()` 内にある配列 `rightRoads` に、上の表の成功率と獲得ポイントを階層ごとに設定しています。配列は0番目から始まるため、`rightRoads[n - 1]` で現在の階層の設定を取り出します。この設定は画面表示と実際の抽選・得点加算の両方に使います。

右の道を選んで全5階層を連続で成功すると、合計 **480pt**（20 + 40 + 60 + 120 + 240）を獲得してクリアできます。

成功・失敗は、1〜100の整数をランダムに生成し、その数が成功率以下かどうかで判定します。
ポイントが加算されるのは成功したときだけです。失敗時はスタミナが減り、ゲームオーバーになるまでは保有ポイントを維持します。

## ⑤工夫した点・こだわった点

- 「もう一度進んで高得点を狙うか、今あるお宝を持って帰るか」という駆け引きを、左右の道と帰還ボタンで表現しました。
- 右の道は階層ごとに成功率と報酬を設定できるようにしました。最終階層は成功率2%・240ptとし、危険を冒して挑戦する選択肢にしています。
- 暗いダンジョンのドット絵、日本語ドットフォント、白枠の会話ウィンドウ、短い効果音で、レトロRPGらしい雰囲気を作りました。
- 成功率・獲得ポイント・スタミナ・残りターンを画面に表示し、次の行動を考えながら遊べるようにしました。
- 成功率と報酬は、表示と実際の判定で同じ設定を参照します。また、終了後の追加操作を止め、やり直し時にはデータと画面表示をまとめて初期化するようにしました。

## ⑥難しかった点・次回トライしたいこと（又は機能）

- if文を使いながら、何が固定で何が変数になるのかの設定に苦労しました
- 公開版ではかなりAIをつかっていますが、基礎となる部分はhtml,cssともに手作業で作成し、一から作ることの難しさを痛感しています
- デザインを作る時点で要件定義をしていることが多くあるなと自分自身に対して思っています。あくまでも事前スキルとして自身が想像がしやすい形なのでいいかなと思っていますが、その裏側にどういった処理を走らせているのかをもう少し具体的にイメージできるようになる必要があると思っています。

### 難しかった点・実装時に整理したこと

- クリア・スタミナ切れ・ターン切れ・帰還の終了条件を整理し、最終階層を超えて進んだり、終了結果が上書きされたりしないようにすること。
- やり直し時に、変数だけでなく、ハート・得点・階層・残りターン・ボタンの有効状態まで初期状態に戻すこと。
- 右の道の成功率と報酬を、一定の計算式から階層ごとの配列設定に変え、画面と判定の両方に反映すること。

### 次回トライしたいこと（改善候補）

- ハイスコアや過去の探索結果を保存し、繰り返し挑戦できるようにする。
- 階層ごとに背景やイベントを変え、奥へ進んだことが見た目でも伝わるようにする。
- 成功率・報酬・ターン数のバランスを調整し、安全な道と危険な道を選ぶ楽しさを高める。

### 画面と操作

暗いダンジョンのドット絵、白枠の会話ウィンドウ、日本語ドットフォントを使ったレトロRPG風の画面です。パソコンとスマートフォンの幅に合わせて表示を調整します。

- 左右の道はカード全体をクリックして選べます。
- 「音 ON」で、探索結果に合わせた短い効果音を有効にできます。初期状態はOFFです。
- 「遊び方」でルールを確認できます。
- キーボードでも操作できます。`←` / `→` で道を選び、`Enter` で進む、`Esc` で帰還、`R` でやり直します。遊び方の表示中は `Esc` で閉じます。

ゲームのルールと判定は `JavaScript/script.js`、背景上の現在地・終了演出・効果音・キーボード操作は `JavaScript/screen.js` が担当します。画面側では確率や得点を計算せず、元のゲーム処理から受け取った状態を表示します。

### 起動方法

`index.html` をWebブラウザで開くと遊べます。VS Codeを利用している場合は、Live Serverなどで開くこともできます。
ビルドやパッケージのインストールは不要です。jQueryは `JavaScript/vendor/jquery-3.7.1.min.js` をローカルから読み込んでいます。

最初から遊び直す場合は、画面の「やり直す」を押してください。

### 使用技術

- HTML
- CSS（Grid・Flexbox）
- JavaScript
- jQuery 3.7.1
- SVG（ハート・矢印アイコン）
- PNG（ダンジョン背景）
- DotGothic16（日本語ドットフォント）
- Web Audio API（効果音）

背景にはデザイン提案で生成したオリジナル画像を使用しています。DotGothic16はGoogle Fontsで配布されているフォントで、ライセンスは `fonts/OFL.txt` に同梱しています。画像・フォント・jQueryはローカルから読み込むため、外部CDNへの接続は不要です。

### 動作確認用テスト

Node.jsが利用できる環境で、プロジェクトのフォルダーから次のコマンドを実行できます。追加のパッケージは不要です。

```sh
node --test tests/game.test.cjs
```

ブラウザの代わりに表示要素とクリックイベントを用意し、実際のゲームコードで、成功率の境界・クリア・ゲームオーバー・ターン切れ・帰還・やり直しを確認します。

現在、右の道に関するテストの期待値に変更前の設定が残っているため、新しい設定に合わせた更新が必要です。
